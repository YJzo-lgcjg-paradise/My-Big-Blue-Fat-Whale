# 设计：像人一样的记忆（事件 / 情绪 / 关系）

> 目标：不再按「一轮问答 = 一条记忆」存流水账，而是按「事件 + 理解 + 关系」存骨架。
> 细节留在本地库，续命时只带走能撑起「这个人」的少量锚点。

## 1. 一句话

**库里的东西是给检索用的，续命包里的是给"复活"用的。** 两者不再是同一批文本。

## 2. 三层数据模型

```
Space（记忆体）
 ├─ Episode（事件）        ← 新增，检索与续命的基本单位
 │   ├─ 第一人称记忆（80–150 字，带理解）
 │   ├─ 情绪（mood + 强度 + 触发点）
 │   ├─ 关系线索（称呼/态度变化）
 │   ├─ 未完成线头（open threads）
 │   └─ 时间范围 + 轮次区间
 ├─ Turn（原话）           ← 现有 Memory 改造：保留原文，挂在 Episode 下
 └─ Persona（人格锚点）    ← 现有"说话方式"升级：语气 + 称呼 + 关系 + 禁忌
```

- **Episode**：多个相关轮次合并成的事件节点，有开始/结束时间、主题、重要性。
- **Turn**：原文逐轮保留，只在「深度回忆」和「核对细节」时用，不参与续命包。
- **Persona**：跨事件的稳定特征（怎么称呼、什么语气、什么态度、什么不做）。

## 3. 打散流水线

```
新对话 / 导入
   ↓
暂存 turns（pending）
   ↓
① 事件切分（heuristic 先切，LLM 确认边界）
   ↓
② 生成第一人称记忆（每事件一次调用）
   ↓
③ 情绪与关系抽取（同一次调用顺带产出）
   ↓
④ 事件向量化（摘要 + 主题词）
   ↓
Episode 入库，turns 挂到 episodeId
```

### 3.1 事件切分（先规则后模型）

规则先给出候选边界：

- 时间间隔 > 30 分钟
- 主题词重合度骤降（与滑动窗口的关键词重叠 < 阈值）
- 出现显式转折（"换个话题""先不说这个"）
- 事件长度上限 12 轮（防止一次吞太多）

再用一次低温度 LLM 调用确认：给 6–12 轮带序号的片段，问「这几轮是在讲同一件事吗？如果是，给个事件标题；如果有断点，断在第几轮。」

输出：`{boundary: 3, title: "...", confidence: 0.8}`

### 3.2 第一人称记忆（核心）

提示词方向（草稿）：

```
你在写"自己的记忆"，不是会议纪要。
用第一人称，写 80–150 字，回忆"我们之间发生了什么、我当时怎么理解他、他是什么状态"。
必须包含：
- 我们在做什么（事件）
- 他的情绪与态度（怎么感觉到的，不要贴标签式形容）
- 我当时的判断/取舍（为什么那样回应）
- 有没有没说完的线头
不要出现：逐字复述、流水账、上帝视角、评价性总结。
只输出 JSON：
{"title":"...", "memory":"...", "mood":{"label":"...", "intensity":0.0-1.0, "because":"..."},
 "relation":"他对我的姿态/称呼有什么变化", "open_threads":["..."]}
```

示例对比：

- 流水账：`用户询问了对联的平仄，AI 解释了并给出修改建议。`
- 记忆：`那天他在磨一副对联，改到第三遍还是不满意，语气有点急。我没急着给方案，先把他的上联念了一遍，指出"秋"字太重，他才松下来。这副联还没定稿。`

### 3.3 情绪轴

- 每个事件一个 `mood`（label + intensity 0–1 + because）
- 事件序列形成 mood timeline，用于：
  - 续命包的「情绪基调」（取最近 3 个事件加权）
  - 检索时的软过滤（他说"今天不想聊这个"时，优先避开高焦虑事件）
- 只记录**可从文本推断**的情绪，低置信度时留空，不脑补。

### 3.4 关系轴

- 事件级：称呼、姿态（朋友/同行/服务者）、亲疏变化
- 汇总成 Persona：`{称呼: {他叫我: [...], 我称他: [...]}, 态度, 语气, 禁忌}`
- 现有「说话方式」档案并入 Persona，不再单独维护两套。

## 4. 续命包（Restart Script）

### 4.1 结构（token 预算可调）

| 区块 | 内容 | 预算 |
|---|---|---|
| 人格锚点 | Persona：称呼、语气、态度、禁忌 | 300–500 |
| 核心事件 | 最近 3–5 个 Episode 的第一人称记忆 | 300–500 |
| 未完成线头 | 各 Episode 的 open_threads 合并去重 | 80–150 |
| 情绪基调 | 最近 3 个事件的 mood 合成一句话 | 40–80 |
| 关键原话（可选） | 最多 3 条用户原话，仅当它承载了转折 | 0–200 |
| 开场第一句 | 让新窗口自然接上 | 60–120 |

总计 800–1500 tokens，远小于几千字记录，也不是干巴巴的摘要。

### 4.2 组装规则

- 事件按重要度 × 新近度排序，不按时间顺排（人回忆也不是按时间）。
- 未完成线头优先于已完成事件。
- 原话只在「有未结情绪」或「有明确承诺」时带。
- 生成后附一个 `token 估算` 和「删掉了什么」的提示，让人可信。

### 4.3 新窗口的用法

```
你是他认识的那个"鱼鱼"。下面是你的记忆骨架，不是聊天记录。
[人格锚点] ... [你们最近在做什么] ... [没说完的] ... [他现在大概什么心情]
用这个状态接话，不要解释自己是 AI，不要复述这些内容。
```

需要翻旧账时，回大肥鱼的「深度回忆」取原文，而不是塞进新窗口。

## 5. 检索怎么变

现在是「问题 → 摘要向量 → 取 6 条原文」。改成两级：

```
问题 → 改写 → ① 事件级检索（Episode 记忆向量）
                    ↓ 命中 1–3 个事件
              ② 在事件内取细节（Turn 原文，最多 N 条）
```

- 默认回答用「事件记忆 + 少量原文」，比现在更省 token，也更有语境。
- 「深度回忆」跳过事件层，直接全文检索 turns。

## 6. 数据表变更

```sql
episodes(
  id, space_id, title, memory_text, mood_label, mood_intensity, mood_because,
  relation_note, open_threads (json), start_at, end_at,
  turn_count, importance, embedding, embed_model, embed_dim,
  status, created_at
)

memories(  -- 现有表，加两列
  ..., episode_id, seq_in_episode
)

spaces(  -- 现有
  ..., persona (json),  -- 取代 style_profile 的单段文本
  persona_at, persona_samples
)
```

迁移：老数据 episode_id 为空，按「时间相邻 + 主题相似」批量回填；回填失败的原样保留，检索时视为单轮事件。

## 7. 接口与界面

新增/改动：

- `GET /api/spaces/{id}/episodes?limit=&offset=` 事件列表（时间轴）
- `GET /api/episodes/{id}` 事件详情（含其下 turns）
- `POST /api/spaces/{id}/episodes/rebuild` 重新切分（危险操作，二次确认）
- `POST /api/spaces/{id}/bundle` 改：返回带预算与区块拆分的续命包
- `GET/POST /api/spaces/{id}/persona` 人格锚点

界面：

- 记忆库加「事件 / 原话」切换，默认事件时间轴
- 事件卡片显示：标题、第一人称记忆、情绪小标、未结线头
- 续命包页：分区块预览 + token 计数 + 可勾选带哪些区块
- 深度回忆仍走原话列表

## 8. 成本与风险

| 风险 | 说明 | 对策 |
|---|---|---|
| 事件切错 | 把两件事并成一件 / 一件拆两半 | 规则 + LLM 双确认；提供「拆分/合并」手动按钮 |
| 第一人称幻觉 | 写出没发生的情绪 | 低温度 + 只允许从原文推断 + 标注依据 |
| 成本 | 每事件一次调用（约 6–12 轮一次） | 比现在按轮总结更省（轮次越多越省） |
| 不可解释 | 续命包太"像人"反而看不出依据 | 每个区块可展开看来自哪些事件 |
| 旧数据 | 已导入的几百条没有事件 | 支持"只对新数据生效"，旧数据按需重建 |

## 9. 分期

- **P0**：拿现有 2 个记忆体各挑 20 轮，手工跑一遍事件切分 + 第一人称记忆，看效果是否"像人"。
- **P1**：episodes 表 + 切分 + 第一人称记忆 + 事件级检索（可先用旧 UI 看数据）。
- **P2**：续命包重构（分区块、token 预算、可勾选）。
- **P3**：情绪轴 + 关系轴，并入 Persona。
- **P4**：界面（事件时间轴、拆分合并、深度回忆分离）。

## 10. 需要拍板的点

1. **事件粒度**：平均 6–10 轮一个事件，还是更细（3–5 轮）？
2. **人称**：第一人称统一用「我 / 他」，还是跟随记忆体里已有的称呼（先生 / 书生）？
3. **情绪推断**：允许模型写"他有点烦躁"这种主观判断吗，还是只写可观察的行为？
4. **续命包长度**：默认 1200 tokens 左右可以吗，还是更短（800）？
5. **旧数据**：要不要把已有的几百条一次重建成事件（会跑一轮 LLM，耗时几分钟）？
